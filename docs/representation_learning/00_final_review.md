# Final review of representation-learning approaches for reciprocal-space data

## Executive verdict

The three specs are not equally close to working. Ranked: **(1) Masked-token MAE on the canonical-ASU sparse voxel set (`03`)**, **(2) VAE on the dense voxel grid (`01`)**, **(3) VICReg contrastive on the dense voxel grid (`02`)**. The MAE wins because (a) it tokenises the data at the right granularity — ~250 sparse-set tokens, not 32 768 mostly-empty voxels; (b) its loss is a per-token cross-entropy on Wilson-E quantile bins, which is the only one of the three losses that puts a unit of supervision on every piece of physically meaningful signal in the input; (c) its output is a token-sequence-shaped representation that cross-attends naturally into modern protein-design backbones (RFdiffusion, AlphaFold-multimer, ESM-3), whereas the VAE produces a single dense vector and the contrastive head produces a dense vector that has been pre-flattened by augmentation invariance. The VAE is a credible secondary, primarily because its reconstruction loss provides a much cleaner falsifiability signal at the 394-protein dev scale than VICReg's collapse-versus-no-collapse dichotomy. The contrastive approach is the weakest of the three at *dev* scale, primarily because VICReg with batch 64 on 394 proteins is a publication-shaped object that learns mostly augmentation invariance and very little reflection physics, and because the spec explicitly throws away side-channels in the encoder rather than forcing the embedding to add information beyond them.

## Approach 1: Masked-token MAE on canonical-ASU sparse voxel set (`03_masked_lm.md`)

### Verdict

**1st. Recommended primary.** This is the right level of abstraction for the data and the right output shape for the downstream user.

### Strong sides

1. **Right tokenisation primitive.** The choice to tokenise only the ~250 nonempty voxels in the canonical ASU and feed the model a sparse set, not the dense 32 768-voxel grid, is the single most important architectural decision in any of the three specs. At 7.5 % occupancy a dense 3D CNN is spending >92 % of its compute on `[EMPTY]` voxels that carry no information; the MAE-set formulation puts every parameter on signal-bearing tokens. This is also why MAE is *cheaper* in practice than the VAE here, despite having more parameters — the sequence is short.
2. **64-bin equal-population quantile vocabulary on Wilson E.** Discrete bins on Wilson-E are physically defensible (η=0.11 on E vs 0.52 on |F| from the analysis) and operationally clean: equal-population means the "predict mode" baseline collapses to 1/64 = 1.6 %, which makes the cross-entropy loss number actually mean something. Adjacent-bin label smoothing (0.8 / 0.075 / 0.025 ramp) correctly treats bins as ordinal — this single choice eliminates a class of pathologies that a one-hot CE on ordered bins is known to fall into.
3. **Block masking at Chebyshev radius r=2 with curriculum from r=1.** Single-voxel masking on a 7.5 %-occupancy grid is a copy-the-neighbour task; the spec author calls this out and addresses it correctly. The r=2 5×5×5 block is sized to the empirical reciprocal-space correlation length (1–3 voxels at n=32, set by the inverse particle size). This matches what works in vision-MAE and point-cloud-MAE.
4. **Conditioning as `[COND]` prefix tokens with stochastic Wilson dropout.** Putting cell, SG, and Wilson profile in as 3 prefix tokens that *every* encoder layer can attend to is more flexible than FiLM (the VAE's choice) — the encoder decides per-token how much conditioning to use. The 50 % Wilson-token dropout is the correct mitigation for the obvious shortcut (back-computing E from |F|² and the radial profile would make the masked-token task degenerate). Both moves are physics-aware.
5. **RoPE-3D positional encoding.** Decouples position from input order (so the spec can shuffle tokens every step and ablate the shuffle without metric movement), and generalises to finer grids (n=64) without retraining the model — a free path to scale up resolution later.

### Weak sides

1. **Sequence-length tail is asserted, not measured.** The spec quotes p95 ≈ 600 and p99 ≈ 900 as expected, with `max_seq_len=1024`. The dev artifact shows median ~250 but the upper tail at n=32 is not in the spec — the analysis voxel-counts parquet should be used to verify before week 1 closes. If p99 is 1300 the spec needs `max_seq_len=2048` or aggressive block-subsampling, and the latter loses information from precisely the high-anisotropy proteins (the ones with the most-occupied wedges).
2. **Decoder is asymmetric MAE-style and is *thrown away* — but the embedding extraction is via a learned attention-pool query**, not the encoder's natural output. This is fine but means the embedding path has not been pretrained with any reconstruction signal — it is downstream-fitted only. In practice this is what MAE always does, but it is a quiet assumption that a single attention-pool query is enough to summarise ~250 tokens for the downstream generator. The downstream consumer should probably take the *full token sequence* via cross-attention, not the pooled vector, to get full benefit (see opportunity 3).
3. **Auxiliary occupancy head over the dense 32³ grid is bolted on.** It cross-attends RoPE-encoded random coordinates into the encoder output and is supervised by a sampled 4 096-coord BCE. This is reasonable but adds a moving part with weight 0.3 that the spec admits will be re-tuned. If gradient norms from this head dominate, the intensity head — the actual point of the model — gets starved. Diagnostic logging of per-head gradient norms should be in week 2, not "if any head dominates".
4. **CD-HIT 30 % at the dev scale of 394 may produce too few clusters.** The spec says 80/10/10 at the cluster level; if the dev set yields, say, 200 clusters, 10 % validation = 20 clusters, with potentially highly variable size — the resulting val metrics will have very wide CIs. This needs bootstrap CIs reported, not point estimates.
5. **No explicit handling of the centric-vs-acentric distinction.** Wilson E for centric reflections is χ²₁-distributed (heavy tail), for acentric is exp(1) (lighter). The 64 equal-pop quantile bins paper over this for the bulk but mis-allocate density at the high-E tail in centric-rich SGs. Spec mentions a one-bin "top-tail" fix in the risks; this should be a default-on, not a fallback.

### Sharpest critique

**The Wilson-token dropout at p=0.5 is necessary but probably insufficient.** The spec author identified that the model can back-compute E by dividing |F|² by the radial profile — but the same shortcut exists *implicitly* via cell tensor + space group + d_min, because Wilson-Σ is a smooth function of resolution and the cell tensor encodes the maximum d* that any voxel can reach. With Wilson-token dropped, the model still has cell + SG, and a sufficiently capable transformer will learn an in-network Wilson estimator from the visible voxels and the resolution implied by the cell. The right fix is to *also* dropout the cell/SG conditioning at, say, p=0.2 each, and to add an explicit **adversarial probe** (frozen-encoder linear probe predicting Wilson-Σ from the embedding *with no `[COND]` tokens visible*) — if that probe achieves R² > 0.5, the embedding is leaking radial structure and is not capturing the anisotropic content the dev analysis identified as the actual signal. This adversarial check is missing from the spec entirely.

## Approach 2: VAE on dense voxel grid (`01_vae_voxel.md`)

### Verdict

**2nd. Recommended secondary as a reconstruction-quality probe and falsifiability signal.** The VAE's reconstruction loss is a number you can read every epoch and immediately know if the model is learning physics; this is more diagnostic value than VICReg gives. But as a primary embedding for the downstream protein generator, the dense-CNN inductive bias and the 64-d single-vector output are both worse fits than the MAE.

### Strong sides

1. **Wilson-E target on channel 0, not log|F|².** The spec correctly chose E² over log|F|² as the reconstruction target, with the radial decay routed to a side-channel. This avoids storing the radial form factor twice and is the single biggest piece of physics-aware design in this proposal. The η-on-E vs η-on-|F| numbers (0.11 vs 0.52) are honoured rather than ignored.
2. **Log-normal NLL on E² over occupied voxels.** Voxel-mean E² is approximately log-normal by CLT (averages of ~exp(1) draws), so log-normal NLL is the right v1 closed-form. The spec's reasoning about the centric/acentric mixture being v2 is correct prioritisation.
3. **FiLM conditioning at every block plus bottleneck concat plus conditioning dropout (CFG-style, p=0.1).** This is the textbook fix for posterior collapse under strong conditioning, and the spec author has clearly seen it before. The orthogonalisation regulariser `(c · z)²` at weight 0.01 is the second textbook fix and is also present.
4. **Symmetry consistency loss `(D(E(g·x), c) − g⁻¹·D(E(x), c))²` at weight 0.1.** Pinning equivariance that the augmentation pipeline only achieves in expectation is exactly the right move at dev scale where the augmentation set is small. This is a stronger form of supervision than the contrastive spec's "symmetry-as-augmentation".
5. **Free-bits at λ=0.5 nats/dim with linear β-warmup.** Posterior collapse is the dominant failure mode of conditional VAEs and the spec has the right preventive measures pre-installed, not as an afterthought.

### Weak sides

1. **Dense 3D CNN at 7.5 % occupancy is wasteful.** ~92 % of the convolution FLOPs are on empty voxels. The spec dismisses sparse conv kernels as "buying nothing", which is accurate per-FLOP at this resolution but misses that a *transformer-on-set* would buy a great deal — the same observation that drives the MAE proposal. The VAE author chose the cheapest-engineering option, not the best inductive bias.
2. **Single 64-d latent vector is the wrong shape for a downstream protein-design generator.** Modern protein backbones consume conditioning via cross-attention from a *sequence* of tokens (residue tokens, MSA columns, structure tokens). A 64-d dense vector will be projected, broadcast, and added to every residue — which means the embedding has to encode whatever the entire reciprocal-space pattern says about every residue in a single 64-d slot. This is information-theoretically tight and architecturally clumsy.
3. **Augmentation set is small.** Only Friedel flip, point-group rotations, and conditional lattice-vector permutation. The spec correctly refuses Gaussian noise on E² (ill-justified for a reconstruction target), but this leaves only ~12 discrete views per protein for a typical SG — and at 394 proteins × 12 = ~4 700 effective unique views, the encoder will memorise. Posterior collapse is the documented risk; *training-set memorisation* is the underdocumented one.
4. **Loss is six-term: BCE occupancy + log-normal NLL on E² + β·KL + 0.1·sym + 0.01·orthogonalisation + (effectively) class-weight on occupancy.** Six terms with three weights to tune is a calibration nightmare. The week-3 sweep priorities are honest about this — but the engineering risk that the sweep finds a local minimum where the model is "fine on every term but not great on any" is real.
5. **Per-protein normalisation breaks cross-protein voxel comparability.** Spec calls this out as a risk and documents the conditioning-tensor mitigation; the mitigation is correct in principle but creates a downstream contract: *the downstream generator must always have access to the matching cell tensor*. This is reasonable for a structure-design generator (it's designing in some target cell) but locks the user out of any cell-free use of the embedding.

### Sharpest critique

**The VAE's 64-d global latent is the wrong unit for downstream conditioning, and no amount of FiLM and free-bits will fix it.** A protein generator needs to know, per-residue or per-region, what the diffraction pattern says about that piece of the structure — the global anisotropy axes, where the resolution drops, where the high-E tail concentrates. A 64-d vector can encode the global summary but not the spatial structure of the conditioning signal. The MAE's token sequence, exposed via cross-attention, gives the downstream model the choice of how to consume the information; the VAE forces a choice (broadcast-and-add) that is rarely the right one. Recommend keeping the VAE as a quality probe (its reconstruction R-factor is a beautiful diagnostic that the MAE's masked-bin CE is not) but not as the primary downstream embedding source.

## Approach 3: VICReg contrastive on dense voxel grid (`02_contrastive.md`)

### Verdict

**3rd. Drop as a primary track. Keep two specific elements of the spec as inputs to the MAE pipeline (see synthesis).**

### Strong sides

1. **Honest about the dev-scale problem.** The spec correctly identifies that InfoNCE / SimCLR are unworkable at 394-protein batch with fold-overlap false negatives, and rejects them in favour of VICReg, which is exactly the right read of the literature for tiny-data SSL. This is not a strength of the *approach*, it is a strength of the *spec author* — they did not over-claim.
2. **Side-channels OFF in the encoder.** This is a defensible design — it forces the embedding to learn cell geometry from the reflection content, not read it off the side-channels. This is in fact the *opposite* of the VAE choice and the MAE choice, and it has merit: any embedding produced this way is by construction not a linear readout of the cell tensor. This earns the spec the strongest "is the embedding informative" guarantee of the three.
3. **Symmetry orbit re-sampling as an augmentation, with explicit 1/|G| identity probability.** Correct stochastic implementation of the SG-equivariance that the data carries. Combined with deterministic ASU canonicalisation as a pre-pass, this is the right factorisation: deterministic projection followed by stochastic orbit re-sampling.
4. **Sub-resolution truncation explicitly rejected as a positive-pair generator.** The reasoning ("forcing invariance to truncation discards exactly the high-q anisotropy that the analysis showed is the strongest signal") is the sharpest piece of physics-aware augmentation thinking in any of the three specs. The author engaged with what the data is telling them and refused a tempting but wrong augmentation.
5. **Alignment / uniformity diagnostics + per-dim variance logging.** Best monitoring suite of the three. Catches collapse fast; provides a continuous health signal during training.

### Weak sides

1. **VICReg invariance loss `||z_a − z_b||²` averages out exactly the anisotropy the dev analysis says is the signal.** The two views differ by symmetry orbit, dropout, noise, and cell jitter — every one of these ought to leave the global anisotropic shape invariant. So far so good. But the protein-to-protein anisotropy *axes* differ (PCA eigenvalue ratio median 3.8, p99 17.6, with directions varying across SGs and cell shapes), and VICReg's variance + covariance terms only enforce that *some* per-dim variance exists across the batch, not that the dimensions track physically meaningful axes. The embedding that VICReg actually learns is the thing that survives all the augmentations — which is roughly: cell volume + d_min + a coarse anisotropy magnitude. Most of the actionable structural signal goes into the projector head and gets discarded.
2. **Augmentation set is too rich for a 394-protein dataset.** Five augmentations, 1000 epochs, batch 64. Each protein sees ~6000 augmentation draws across training. With only 394 training items, VICReg learns to be invariant to its own augmentation set with high confidence and to encode whatever residual cross-protein variation survives — which is a small, dataset-size-bounded amount of information. The spec admits this in the open questions but the mitigation ("real test is full-PDB") is a deferral, not a fix.
3. **No reconstruction signal anywhere.** The model has no per-voxel supervision; it only has same-protein-vs-different-protein supervision. This is the lightest possible signal density per training item, which is exactly the wrong choice at dev scale where signal-per-item is the binding constraint. (MAE has ~150 supervised tokens per protein per step. VAE has ~2 500 supervised voxels per protein per step. VICReg has *one* supervised pair per protein per step.)
4. **Single 256-d output vector — same downstream-shape problem as the VAE.** Plus the projector-vs-encoder discipline (`h` for downstream, `z` for loss only) means the spec's diagnostics measure `h` quality but the actual training pressure is on `z`. The gap is well-documented in the SimCLR literature but is invisible to the per-step variance log.
5. **"Augmentations enforce equivariance in expectation" is exactly the same compromise the VAE makes**, but without the VAE's symmetry consistency loss to pin it down. VICReg has *no* explicit equivariance term — only invariance. The spec's claim that this is sufficient relies on the augmentation pipeline being a good sampler of the symmetry group, which at small batch and few groups it is not.

### Sharpest critique

**VICReg on 394 proteins with batch 64 is a dataset-augmentation classifier, not a reflection-physics learner.** With ~6000 effective augmented views per protein and only 394 distinct proteins, the model's optimal solution is to memorise per-protein identity (the augmentation manifold) and then add a thin layer of cross-protein discrimination on top. The variance + covariance terms guarantee non-collapse but do not guarantee the embedding tracks any physically meaningful axis. The standard SSL mitigation — scale to millions of items — is exactly what the dev set cannot provide. The spec's go/no-go criterion (linear-probe anisotropy R² ≥ 0.7) is achievable by an encoder that has learnt only "big cell vs small cell, isotropic vs anisotropic", which is a fraction of the signal the MAE will learn. This approach is most likely to *appear* to work at dev scale by passing its weak probes, while in fact carrying a thin embedding. Do not deploy it as the primary track.

## Final summary for representation learning

### Recommended primary

**MAE on the canonical-ASU sparse voxel set (`03`).** It is the only one of the three approaches whose unit of supervision (a Wilson-E quantile bin per masked token) matches the unit of physical signal (per-voxel anisotropy in Wilson-normalised intensity), and whose output shape (a token sequence of ~250 entries) matches what modern protein-design backbones consume via cross-attention.

### Recommended secondary

**Run the VAE (`01`) in parallel as a method-selection candidate and a reconstruction-quality probe**, with the MAE as the recommended primary to scale and the VAE as the recommended secondary to scale alongside (or as an ablation if the MAE's mechanism diagnostics are unambiguously clean). Train it on the same canonical-ASU + Wilson-E + cell-and-SG side-channel pipeline used for the MAE so the two are compared on equal footing; surface the FiLM-conditioning-doing-its-job diagnostic and the posterior-collapse diagnostic on the dev set as part of the bake-off (see Week 2 plan). Independently of the bake-off outcome, use the VAE's reconstruction R-factor and per-shell occupancy F1 as a *physical* falsifiability signal that the MAE's CE-on-bins cannot directly provide; the VAE's 64-d latent also provides a useful "what does the model think the global summary is" diagnostic, evaluable by linear probes on cell volume, d_min, and anisotropy ratio (informational at dev scale, gating at full-PDB scale). Run the VAE at 30 % of the MAE's compute budget; do not let it consume engineer-time on its own conditioning sweeps.

### Disposition of the third

**Drop VICReg (`02`) as a track.** Lift two specific elements from the spec into the MAE pipeline:
- The augmentation taxonomy (especially the rejection of sub-resolution truncation as a positive-pair generator and the explicit Friedel-flip / symmetry-orbit handling) — adopt verbatim for the MAE training loop where applicable.
- The alignment / uniformity / per-dim-variance diagnostic suite — port to the MAE's attention-pooled embedding as a collapse-detection sanity check.

**Trigger to revive contrastive:** if and only if the full-PDB scale (≥150 k proteins) is reached and the MAE shows symptoms of saturation that a contrastive cross-protein objective could plausibly fix (e.g. linear-probe anisotropy R² plateaus below 0.95 on a 50 k validation set). At dev scale, contrastive is dominated.

### Three cross-cutting risks

1. **ASU canonicalisation correctness.** All three specs depend on `gemmi`'s `ReciprocalAsu.to_asu` returning canonical Miller indices that agree across symmetry-equivalent inputs to within rounding, including for the 88 % of representatives currently outside the canonical ASU. A single wrong sign or index permutation contaminates *every* downstream embedding and is undetectable by reconstruction loss alone (the model just learns the wrong canonicalisation). **Mitigation:** before week 1 of any track, write a unit test that takes a reflection list, applies a random non-identity SG operation, re-canonicalises, and asserts byte-for-byte equality with the original canonical form. Run on all 394 dev proteins. Fix `gemmi` version in the lockfile.

2. **Wilson-Σ noise on small proteins.** The Wilson radial profile is fitted from binned `⟨|F|²⟩(d*)`. Small proteins with few reflections per shell give noisy Σ estimates, which propagate into noisy E values, which propagate into noisy bin assignments (MAE) or noisy reconstruction targets (VAE). At the dev scale of 394 proteins this includes the long tail of small proteins where the signal is most fragile. **Mitigation:** the VAE spec's shrinkage estimator (shrink toward the global mean profile with weight `1/(1 + n_shell/50)`) should be the **shared default** across all three pipelines. Verify with a held-out small-protein subset that bin assignments are stable under bootstrapped reflection subsampling.

3. **Cell-tensor and SG-token leakage into the embedding.** All three specs route cell + SG into the model in some form. The VAE and MAE feed them as conditioning; the contrastive spec withholds them. The risk is that the embedding's downstream-useful information becomes "what the cell tensor says" in a form already available to the downstream generator from its own inputs. **Mitigation:** make the linear-probe-from-`[COND]`-only diagnostic a default reporting metric on every checkpoint of every track. The reportable number is *the gap* between full-encoder probe accuracy and `[COND]`-only probe accuracy — that gap is the signal-bearing portion of the embedding. At dev scale this gap is a *mechanism* indicator, not an absolute bar: a non-zero, non-decreasing gap that grows with training is the diagnostic signature that the encoder is learning reflection content beyond what the conditioning already provides. A gap that is flat or shrinking with training (especially when paired with a high `[COND]`-only probe) signals that the conditioning-leakage failure mode is active and uncontrolled — and at full PDB scale, that translates directly into "the embedding is mostly conditioning, not reflection content." Treat the *gap dynamics* as the dev-scale diagnostic; treat absolute thresholds as a downstream-evaluation concern.

### Three cross-cutting opportunities (your additions)

1. **Use `[COND]`-prediction as auxiliary self-supervision rather than only as a leakage diagnostic.** All three specs treat cell, SG, and Wilson profile as inputs (or, in the contrastive case, as withheld inputs). At dev scale none of the three has enough cross-protein signal to learn a strong embedding from scratch. Instead: take 50 % of the time, **predict** the cell tensor, the SG token, and a coarse d_min from the embedding (frozen-encoder MLP head, MSE / CE / MSE losses). This gives every protein 6 + log(65) + 1 ≈ ~13 nats of free supervision per training step — a curriculum signal that costs nothing and that is structure-aware rather than augmentation-aware. The MAE spec's adversarial leakage probe becomes a shared head that is *trained*, not just evaluated. Net effect: the encoder is forced to encode the cell geometry implicitly (since the conditioning is available but the prediction head sees only the encoder output), which is the contrastive spec's best instinct, applied as a soft auxiliary instead of a hard architectural decision.

2. **Pretrain the MAE, then *fine-tune the encoder inside a VAE objective* in a second stage.** The MAE's CE-on-bins task gives the encoder a sharp, per-token signal to bootstrap on. The VAE's continuous-E reconstruction gives a smoother, decision-relevant downstream signal but is harder to optimise from scratch at small scale. Two-stage training — MAE → VAE-with-MAE-init — combines them: stage 1 gives the encoder the right inductive bias for sparse-set reflection physics; stage 2 specialises the decoder for the continuous reconstruction task that downstream R-factor evaluation cares about. This costs one extra training stage and ~30 % more total compute but is dominated by both standalone alternatives in expectation. None of the three specs proposes this composition.

3. **Reciprocal-space embedding's unique contribution vs ESM and structure embeddings is *crystal-form-dependent anisotropy*, and nothing else.** ESM-2/3 already encodes sequence; AlphaFold and structure-token models encode coordinate geometry; the unique value-add of a reciprocal-space embedding is the *experimental* anisotropy axes — how the diffraction pattern is shaped by *this* crystal, in *this* space group, at *this* resolution. Any signal that ESM or AF can already predict from sequence (e.g. fold class, broad cell-volume regularities) is *not* what the reciprocal-space embedding should be optimising for; in fact, training on those signals risks producing an embedding that is downstream-redundant. The opportunity: design a final-stage evaluation that **conditions on ESM features as a control**, freezes them, and asks how much variance in downstream tasks (e.g. R-factor reduction in a structure-refinement proxy task) is explained by the reciprocal-space embedding *over and above* ESM. Linear-probe-on-anisotropy is necessary but not sufficient; ESM-conditioned probes are the actual go/no-go for downstream usefulness.

### Two-week empirical bake-off plan

**Framing.** The dev set is a **proof-of-concept and method-selection harness**, not a representation-quality benchmark. The goal of the two weeks is not to learn good embeddings on 394 proteins — that is not achievable and not the bar — but to establish that the chosen pretraining objective produces a working gradient signal with the inductive biases the spec promises, on a scale where we can iterate in hours rather than days. We are choosing which method to scale to the full PDB, where representation quality will actually be earned. Accordingly, the bake-off measures **mechanism** (is the loss landscape behaving as designed? are the named failure modes visible and controllable? are the engineering primitives correct?) and **predictable scaling** (is the loss-vs-data curve still descending at n=394?), not absolute probe accuracy. The absolute probe numbers from the previous draft of this plan are kept below as *informational* read-outs, but they are no longer gate criteria — a method that passes the mechanism checks and shows a descending scaling curve scales, regardless of what its 394-protein probe R² happens to be, and a method that fails the mechanism checks does not scale even if its probe numbers look respectable.

**Goal:** prove or kill the recommended primary (MAE) as a *scalable strategy* on the 394-protein dev set before committing to full-PDB compute. Two engineer-weeks. Single A100-40GB.

**Week 1 — pipeline, baselines, and the engineering-primitive checklist.**

- Day 1–2: Implement the shared canonical-ASU + Wilson-Σ-with-shrinkage + side-channel-extraction pipeline once, used by both MAE and VAE. Unit-test ASU canonicalisation against random SG operations on all 394 dev proteins (this is a primitive that *must* be correct before any scale run; bake-off ticks it off explicitly). Verify p95 / p99 sequence length on the canonical-ASU sparse set (the MAE spec's open question 1) — gate on `p99 ≤ 1024`; if not, switch to `max_seq_len=1536` and document.
- Day 3: Build the MAE tokeniser (64 equal-pop quantile bins on Wilson E, 5 count buckets), persist `bin_edges_v1.npy`. Verify train marginal is uniform to within 1 %, val is within 3 %. Verify symmetry-augmentation correctness: applying every SG operation in the orbit and re-canonicalising must return the same token sequence up to RoPE-3D positional re-keying.
- Day 4: Build CD-HIT 30 % cluster split, persist. Confirm no val protein has BLAST ≥ 30 % to any train protein. (Note: the cluster count at n=394 will be small and the val-set is too narrow to ground absolute probe numbers — this is expected and not a defect of the bake-off.)
- Day 5: Run two **untrained** baselines on the informational linear probes (SG, cell volume, d_min, anisotropy ratio): (a) random-init MAE encoder, attention-pool readout; (b) `[COND]`-only readout (cell + SG + Wilson profile passed through small MLP, no reflection content). These set the floor for the over-conditioning gap diagnostic.

**Engineering-primitives checklist (Week 1 deliverable, gates Week 2):**
- [ ] ASU canonicalisation is byte-stable under random non-identity SG operations on all 394 dev proteins.
- [ ] Sparse-COO loader returns deterministic token order under a fixed seed; RoPE-3D keys are stable under shuffle.
- [ ] Wilson-Σ shrinkage estimator stabilises bin assignments under bootstrapped reflection subsampling on the small-protein subset (KL ≤ 0.05 between bootstrap replicates).
- [ ] Symmetry-augmentation orbit is a faithful sampler of the SG: applying `g` then `g⁻¹` is a no-op on tokens and on side-channels.
- [ ] Wilson-E quantile bin marginals are uniform on train (≤ 1 %) and val (≤ 3 %).

**Week 2 — train, surface failure modes, measure scaling, decide.**

- Day 6–8: Train MAE for 200 epochs at the spec's hyperparameters. Log per-step: masked-token CE, top-1 / top-5 bin accuracy (informational), attention-pool variance and uniformity, gradient norms per head, per-shell reconstruction Pearson R on E. Checkpoint every 25 epochs.
- Day 9 — **mechanism test 1, anisotropic-vs-radial control.** Compute masked-token reconstruction Pearson R on E on the val set, then compute the same Pearson R against a **radially-shuffled control** (each masked voxel's target is replaced by a random voxel drawn from the same `d*` shell, preserving the radial profile but destroying the directional pattern). The MAE is exhibiting the inductive bias the spec promised iff `R(E) − R(radially-shuffled) ≥ 0.10` — i.e. the model is using directional information, not just radial decay. This margin is the diagnostic; its absolute value is not.
- Day 10 — **mechanism test 2, conditioning leakage.** Run the adversarial leakage probe (Wilson-Σ regression from the embedding with all `[COND]` tokens hidden). Pass criterion: leakage R² < 0.5 *with* the cell/SG dropout (see ablation Day 11–12); if it cannot be pushed below 0.5 by any setting in the sweep, the conditioning channel is not controllable and the run is a fail on this method.
- Day 11–12 — **mechanism test 3, named failure-mode surfacing.** Targeted ablations on the most uncertain choices: `[COND_wilson]` dropout ∈ {0.0, 0.5, 0.8}; cell + SG dropout ∈ {0.0, 0.2}; block radius r ∈ {1, 2, 3}; mask ratio ∈ {0.45, 0.60, 0.75}. Three runs each, 100 epochs. The point of this sweep is not to find a winning hyperparameter — the dev set is too small for that — but to confirm the named failure modes (mask leakage via positional encoding; shortcut-via-Wilson; per-head gradient starvation when the occupancy aux dominates) are *visible* and *controllable* by these knobs. A failure mode that the dev set does not surface is one that will burn weeks of full-PDB compute.
- Day 13 — **scaling-curve test.** Re-run the chosen MAE configuration on n ∈ {100, 200, 394} proteins (subsets nested) for a fixed compute budget (e.g. 80 epochs at full size, scaled by training-set size to keep gradient steps comparable). Plot val masked-token CE and val reconstruction Pearson R vs `log(n)`. Fit a 3-point trend. The signature of a scalable method is **monotonic improvement with negative second derivative not yet reaching zero** at n=394 — i.e. the method is still data-hungry. A flat curve at 394 means the method is data-saturated at this scale and we cannot extrapolate; a still-descending curve means scaling to 150 k is justified.
- Day 14 — **cross-method side-by-side.** Run the equivalent diagnostic suite on the VAE secondary (same Days 6–13 timeline, compressed and run in parallel by the VAE engineer; see secondary section). Produce a side-by-side table on the mechanism metrics for MAE and VAE: loss-descent profile, anisotropic-vs-radial margin (for VAE: reconstruction R on E vs reconstruction R on the radially-shuffled control), conditioning-leakage R² with and without the conditioning side-channel ablated, scaling-curve slope at n=394, named-failure-mode surfaceability. Recommend a single primary to scale and a single secondary to scale alongside.

**VAE-side mechanism test (parallel, Days 6–14).** Train VAE for 150 epochs on the shared pipeline. The VAE's named diagnostic for "conditioning is doing its job" is: a frozen-encoder linear probe of cell volume from the latent should be **worse** when the cell-tensor side-channel is provided to the FiLM decoder than when it is withheld, because the conditioning is supposed to absorb cell information rather than letting it propagate to the latent. Concretely: train two VAEs with identical hyperparameters except that one withholds the cell tensor from the decoder; the cell-volume probe R² from the latent should be at least 0.15 R² *higher* in the with-held variant. If the gap is ≤ 0.05, the FiLM conditioning is decorative and the latent is doing the work the conditioning was supposed to do — that is a method-fail signature on the VAE, in 3 days, on the dev set, exactly as the harness is supposed to surface. Posterior collapse is the second VAE-named failure mode and is detectable by per-dim KL (any dim with `KL < 0.01 nats` for ≥ 30 epochs is collapsed); a healthy VAE under free-bits at λ=0.5 should have ≥ 50 % of dims active.

**Informational read-outs (not gate criteria).** Frozen attention-pool linear probes for SG top-1, log cell volume R², d_min R², and anisotropy ratio R², plus the over-conditioning gap on anisotropy. These are interesting if they happen to be high — they were the gate criteria in the previous draft of this plan and are kept here for continuity with downstream-evaluation work — but a 394-protein dev set is too narrow to ground absolute thresholds, and chasing them risks selecting a method that overfits to the dev probes rather than scales. The previous numerical thresholds (SG top-1 ≥ 0.50, cell-volume R² ≥ 0.85, anisotropy R² ≥ 0.60, over-conditioning gap ≥ 0.20) are **not** the bar and should not be treated as such by future readers.

**Go / no-go metric (single sentence):** the MAE primary track is a go for full-PDB scale if and only if (i) the engineering-primitives checklist is fully ticked, (ii) the masked-token CE descends and saturates within the 200-epoch budget without diverging or plateauing in the first 25 epochs, (iii) the anisotropic-vs-radial reconstruction margin is ≥ 0.10 and (iv) the conditioning-leakage R² can be pushed below 0.5 by the dropout sweep, (v) at least one of the named failure modes is observed *and* controlled by a sweep knob (proving the harness can surface and fix what it is supposed to), and (vi) the n ∈ {100, 200, 394} scaling curve on val masked-token CE is monotonically improving with the trend at n=394 not yet flat — i.e. the method is exhibiting the diagnostic signature of working as designed and is data-hungry rather than data-saturated.

### If the bake-off fails

A bake-off "fail" means one of: loss does not descend or plateaus inside the first 25 epochs; the anisotropic-vs-radial control margin is below 0.10 (the model is learning radial decay, not anisotropy); the conditioning-leakage R² cannot be pushed below 0.5 by any dropout setting (the conditioning channel is uncontrollable on this objective); or the n ∈ {100, 200, 394} scaling curve is flat (the method has hit its capacity at this scale). Distinguish two cases. **Case A — the method is broken on this data.** The mechanism diagnostics fail, the curve is flat, and the failure mode is identified and not controllable: pivot to the VAE secondary as the new primary. The canonical-ASU + Wilson-Σ + cell-and-SG-conditioning + symmetry-loss pipeline transfers almost unchanged, and the VAE's reconstruction R-factor is a sharper failure-mode diagnostic at small scale than the MAE's masked-CE. **Case B — the dev set is too small to discriminate.** Loss descends, mechanism diagnostics are ambiguous (e.g. anisotropic-vs-radial margin is between 0.05 and 0.10), the scaling curve is still descending but the slope at n=394 is noisy. This is *acceptable* — the dev set was never going to ground a fine method comparison. Proceed to scale anyway with one cheap full-PDB run (≤ 10 % of the full training budget) as the discriminator, on the basis that the mechanism diagnostics did not reveal a broken method. If the VAE *also* exhibits a Case A fail under its own mechanism harness — broken loss landscape, decorative FiLM, posterior collapse uncontrollable — the conclusion is that no current SSL objective is exhibiting a scalable signature on this data class, and the project should pause representation-learning entirely until the full-PDB pipeline is online to provide a stronger discriminator, rather than deploy VICReg as a Hail Mary (the contrastive approach was dominated on dev-scale signal density and would not be revived by a Case A failure of the other two).
